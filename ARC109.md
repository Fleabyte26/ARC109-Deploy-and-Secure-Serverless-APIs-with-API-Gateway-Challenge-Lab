# ARC109 - Develop and Secure APIs with API Gateway: Challenge Lab

Paste the blocks in order in one Cloud Shell tab. Every block has the commands and ends with a check line, compare it with the note under the block.

## Known lab traps/bugs (read first)

1. The first function deploy can fail because the lab's services are still starting up (the lab says so itself). If block 1b ends with an error, wait 2 minutes and paste it again.
2. The lab's openapispec.yaml has two placeholders, PROJECT_NUMBER and REGION, that you must replace. Left as they are, the gateway is created but points nowhere. Block 2a fills them in.
3. The gateway takes about 10 minutes to create. Block 2b just sits there until it is done: do not close Cloud Shell and do not paste the next block early.
4. Task 3 is only scored after a message really reaches the topic. That means: topic first, then redeploy, then call the gateway. Messages can take a few minutes to show up, so wait before deciding the check failed.
5. The region is different in every lab instance. Setup reads it for you, compare it with the region in Task 1 of the lab.

## Setup

Nothing to edit.

```bash
gcloud config get-value project > ~/project
gcloud projects describe `cat ~/project` --format='value(projectNumber)' > ~/projnum
gcloud compute project-info describe --format=json | grep -A1 'google-compute-default-region' | grep '"value"' | cut -d'"' -f4 > ~/region
test -s ~/region || gcloud config get-value compute/region > ~/region
gcloud services enable apigateway.googleapis.com servicemanagement.googleapis.com servicecontrol.googleapis.com
gcloud beta services identity create --service=cloudfunctions.googleapis.com
head ~/project ~/projnum ~/region
```

You should see your project ID, project number and a region that matches the one in Task 1 of the lab. If the region is empty or different, write it by hand, for example `echo "us-east1" > ~/region`. A "permission denied" on the two lines before the last is fine, the lab has those services ready.

## Task 1. Create a Cloud Run function

### 1a. Write the Hello World code

```bash
mkdir -p ~/gcfunction && cd ~/gcfunction
cat > index.js <<'EOF'
const functions = require('@google-cloud/functions-framework');

functions.http('helloHttp', (req, res) => {
  res.status(200).send('Hello World!');
});
EOF
cat > package.json <<'EOF'
{
  "dependencies": {
    "@google-cloud/functions-framework": "^3.0.0"
  }
}
EOF
ls ~/gcfunction
```

You should see index.js and package.json.

### 1b. Deploy it (2nd gen, Node.js 22, public)

```bash
cd ~/gcfunction
gcloud functions deploy gcfunction --gen2 --runtime=nodejs22 --region=`cat ~/region` \
  --trigger-http --allow-unauthenticated --entry-point=helloHttp --source=. --quiet
curl -s "https://gcfunction-`cat ~/projnum`.`cat ~/region`.run.app" ; echo
```

You should see the deploy finish (state ACTIVE) and then Hello World! If the deploy fails, wait 2 minutes and paste the block again.

## Task 2. Create an API Gateway

### 2a. Write the spec, create the API and its config

The spec is the lab's file with the two placeholders filled in. The config is tied to the Compute Engine default service account, as the lab's table asks.

```bash
cd ~
cat > openapispec.yaml <<'EOF'
swagger: '2.0'
info:
  title: gcfunction API
  description: Sample API on API Gateway with a Google Cloud Run functions backend
  version: 1.0.0
schemes:
- https
produces:
- application/json
x-google-backend:
  address: https://gcfunction-PROJECT_NUMBER.REGION.run.app
paths:
  /gcfunction:
    get:
      summary: gcfunction
      operationId: gcfunction
      responses:
        '200':
          description: A successful response
          schema:
            type: string
EOF
sed -i "s|PROJECT_NUMBER|`cat ~/projnum`|; s|REGION|`cat ~/region`|" openapispec.yaml
gcloud api-gateway apis create gcfunction-api --display-name="gcfunction API"
gcloud api-gateway api-configs create gcfunction-api --api=gcfunction-api \
  --display-name="gcfunction API" --openapi-spec=openapispec.yaml \
  --backend-auth-service-account=`cat ~/projnum`-compute@developer.gserviceaccount.com
grep address openapispec.yaml
gcloud api-gateway api-configs list --api=gcfunction-api --format='value(name.basename(),state)'
```

You should see the address line with your project number and region in it (no PROJECT_NUMBER or REGION left), then gcfunction-api ACTIVE.

### 2b. Create the gateway (about 10 minutes, wait for it)

```bash
gcloud api-gateway gateways create gcfunction-api --display-name="gcfunction API" \
  --api=gcfunction-api --api-config=gcfunction-api --location=`cat ~/region`
gcloud api-gateway gateways describe gcfunction-api --location=`cat ~/region` --format='value(defaultHostname)' > ~/gw
cat ~/gw
curl -s "https://`cat ~/gw`/gcfunction" ; echo
```

You should see a hostname ending in gateway.dev and then Hello World!, this time coming through the gateway. If the last line shows an error page, the gateway needs another minute: paste only the curl line again.

Check my progress: Create an API Gateway.

## Task 3. Create a Pub/Sub topic and publish messages through the API

### 3a. Create the topic with its default subscription

```bash
gcloud pubsub topics create demo-topic
gcloud pubsub subscriptions create demo-topic-sub --topic=demo-topic
gcloud pubsub subscriptions list --format='value(name.basename(),topic.basename())'
```

You should see demo-topic-sub demo-topic.

### 3b. Update the function so it publishes a message, and redeploy

```bash
cd ~/gcfunction
cat > package.json <<'EOF'
{
  "dependencies": {
    "@google-cloud/functions-framework": "^3.0.0",
    "@google-cloud/pubsub": "^3.4.1"
  }
}
EOF
cat > index.js <<'EOF'
const {PubSub} = require('@google-cloud/pubsub');
const pubsub = new PubSub();
const topic = pubsub.topic('demo-topic');
const functions = require('@google-cloud/functions-framework');

exports.helloHttp = functions.http('helloHttp', (req, res) => {

  // Send a message to the topic
  topic.publishMessage({data: Buffer.from('Hello from Cloud Run functions!')});
  res.status(200).send("Message sent to Topic demo-topic!");
});
EOF
gcloud functions deploy gcfunction --gen2 --runtime=nodejs22 --region=`cat ~/region` \
  --trigger-http --allow-unauthenticated --entry-point=helloHttp --source=. --quiet
curl -s "https://gcfunction-`cat ~/projnum`.`cat ~/region`.run.app" ; echo
```

You should see the deploy finish and then: Message sent to Topic demo-topic!

### 3c. Call the function through the gateway and look for the message

```bash
curl -s "https://`cat ~/gw`/gcfunction" ; echo
curl -s "https://`cat ~/gw`/gcfunction" ; echo
curl -s "https://`cat ~/gw`/gcfunction" ; echo
sleep 60
gcloud pubsub subscriptions pull demo-topic-sub --limit=3 --format='value(message.data.decode(base64))'
```

You should see Message sent to Topic demo-topic! three times, then at least one line saying Hello from Cloud Run functions! If the last command prints nothing, wait 2 minutes and run only that line again.

Check my progress: Create a Pub/Sub Topic and Publish Messages via API Backend.
